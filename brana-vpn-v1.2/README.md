# Brana VPN · 浏览器专属加速

基于 `chrome-route-extension`（Brana 智能选路）重新设计的**浏览器专属 VPN**：只接管 Chrome / Edge 的流量，全局按「**节点 + ProxyIP**」运行，按 **连通性 → 延迟 → 速度 → 稳定性** 自动选出最优线路，并持续守护、自动容灾。原插件未做任何修改。

```
浏览器（只代理浏览器） → 本地核心 127.0.0.1:17890 → 节点（VLESS/Trojan · WS+TLS） → ProxyIP → 目标网站
```

---

## v1.2.8 更新（IPPure 风险系数 · 高风险自动拉黑）

- **数据源：** 纯净度改为以 **IPPure** 为准（基于风险信息库与蜜罐记录）。IPPure 托管在 Cloudflare 上，插件经节点用每个 ProxyIP 访问它，拿到的就是这个出口自己的风险系数、住宅 / 机房、原生 / 广播。结果按实际出口 IP 缓存 3 天。
- **纯净度换算：** 纯净度 = 100 − IPPure 系数。没有 IPPure 结果时，仍按原来的 ip-api + proxycheck 计算。
- **自动拉黑：** IPPure 系数 **≥ 51**（中度、高度风险），或查询时被 Cloudflare 人机验证拦截的，不参与选线、换 IP 和备用线路；当前线路变成高风险时，后台会自动换掉。上限可在「设置 → 高级参数 → IPPure 风险上限」修改，填 100 表示不拉黑。
- **临时放宽：** 所有可用 IP 都超过上限时，临时用风险最低的那个（连通性优先），概览页显示「临时放宽」。
- **ProxyIP 页：**
  - 新增「IPPure」检测按钮和「高风险」筛选；
  - 被拉黑的 IP 显示「高风险 xx%」或「CF 拦截」，状态列显示「拉黑」。
- **概览页：** 出口卡片显示当前出口的 IPPure 系数。
- **实测（2026-10-21，公共 ProxyIP 池）：** 25 个中约 60% 低于 51。统一出口用的通用转发 IP 都在 83–87%，开启统一出口时基本会处于「临时放宽」状态。
- 不需要更新核心（使用核心已有的 fetch 接口，`via:'tunnel'` 只经节点查询，失败时不会直连）。

## v1.2.7 更新（直连兜底默认关闭）

- 「直连兜底」改为**默认关闭**，从旧版升级时会自动关闭一次；之后你手动打开，不会再被改回。
- 原因：兜底是按单个连接触发的。某个连接的线路全部失败时会悄悄直连，网站会看到真实 IP（AI 类网站可能因此风控），被墙的网站直连本来也打不开，而且会破坏「统一出口」。
- 「严格防泄漏」默认仍为关闭。经常用 AI 账号建议手动打开：这样核心重启或崩溃的空档里也不会直连，代价是空档期间走代理的网站打不开（扩展每 30 秒自检，并自动拉起核心）。
- Chrome DNS 预取不做修改：规则中不做本地 DNS 查询，走代理的域名由核心远程解析；关闭预取会拖慢整个浏览器，收益很小。

## v1.2.6 更新（统一出口：所有网站同一个 IP）· 需要核心 1.2.4

**问题**：edgetunnel 只在访问 Cloudflare 托管的网站时经 ProxyIP 出去，其他网站从 Worker 出去（104.28.x，Cloudflare WARP 段），所以不同网站看到的 IP 不一样。

**原理**：大约 5% 的公共 ProxyIP 是「通用转发」型，能按 SNI 转发任意 HTTPS 网站。核心 1.2.4 的线路新增 `uni` 参数：把 443 端口的域名连接目标改写为这个 ProxyIP，由它按 SNI 转发。这样 Cloudflare 和非 Cloudflare 网站看到的都是它的 IP。

- **设置 → 常用 → 统一出口**（默认关闭）。开启后：
  - 自动扫描通用转发 ProxyIP，只在这些 IP 中选线、换 IP、做备用线路；
  - 一个都找不到时，按普通模式连接，概览页会显示「统一出口未生效」。
- **严格统一出口**：无法统一的连接（非 443 端口、直接访问 IP）直接拒绝。关闭时这些连接仍经节点发出，出口为 Worker IP。
- **判定方法**：经节点让 ProxyIP 分别转发 Cloudflare trace 和 ipinfo.io，两边出口 IP 一致才算「通用」。同时检测能否转发 HTTP 80 端口，能的话 80 端口也一起统一。结果缓存 24 小时（失败的缓存 12 小时）。
- **ProxyIP 页**：新增「扫描通用」按钮、「通用」筛选和标签。
- **概览页**：出口卡片显示「统一出口 ✓ / 出口不一致」；「其他网站」出口改用 HTTPS 的 ipinfo 检测。
- **核心 1.2.4**：
  - 新增 `uni` / `uniHttp` / `uniStrict`，`FEATURES` 增加 `uni`；
  - 移除无效的 TLS 指纹试验（tlsProfile）。

**限制**：
- 只能统一 HTTPS（加上可转发 80 端口的 ProxyIP 的 HTTP）。
- 速度受这个 ProxyIP 本身限制，实测 48–72 Mbps。
- 公共通用转发 IP 很少，也可能随时失效，而且它们是别人的服务器，请自行评估风险。
- 想要稳定的单一出口，更可靠的方案是在 edgetunnel 中配置你自己的 SOCKS5 全局出口（`/socks5://…` 路径）。

## v1.2.5 更新（ProxyIP 纯净度 + 住宅 / 机房检测，住宅纯净高速优先）

- **自动检测每个 ProxyIP 的类型与纯净度**：ip-api.com 批量查询（机房 / 代理 / 移动标记）+ proxycheck.io 风险分（类型：住宅 / 商业 / 机房 / VPN），再按运营商名称兜底识别。结果缓存 7 天。
  - 类型：住宅、移动、ISP（运营商线路）、商业、机房；纯净度 0–100（= 100 − 风险分，再扣代理 / 机房标记）。
  - 每轮优选先对整个池预筛（ip-api，免费额度充足），通过检测的候选再深查 proxycheck。手动「检测」也会顺带检测。
  - proxycheck 无 key 约 100 次/天（按 ProxyIP 计，公共 IP 可能已被他人用完）；可在设置填免费 key（1000 次/天）。查不到时自动只用 ip-api。
- **选线：住宅纯净且够快的优先**（设置 → 高级参数 → ProxyIP 质量偏好）：
  - 住宅纯净优先（默认）：住宅 / 移动且纯净、速度 ≥ 50 Mbps ×0.2；运营商线路纯净 ×0.3；其他纯净 ×0.6；不纯净 ×1～1.3。
  - 住宅 IP 测得太慢（低于「优先 IP 最低速度」）就失去优先，不会为了「干净」牺牲速度。
  - 每轮候选为住宅 / 纯净 IP 预留约 40% 名额，保证它们有机会被测到。
  - 也可选「纯净优先（不限类型）」或「不参与选线（只显示）」。
- **界面**：ProxyIP 列表新增「质量」列（如「住宅 100」「机房 4」，悬停看运营商、风险分、实测速度），筛选新增「住宅」。
- **注意**：ProxyIP 只决定 Cloudflare 托管网站（如 ChatGPT、Claude、Discord）看到的 IP；其他网站看到的是 Worker 出口（104.28.x），与 ProxyIP 无关。实测公共列表中的住宅 ProxyIP 多数不可用或很慢。

## v1.2.4 更新（按 ProxyIP 实际带宽选线）

- **问题**：同一节点、延迟相近的 ProxyIP，访问 Cloudflare 网站的带宽可差 100 倍（实测 4 Mbps ～ 400 Mbps）。旧版选线只比延迟，测速又用 Linode（不在 Cloudflare 上、不经 ProxyIP，且自身波动 6～290 Mbps），所以测不出 ProxyIP 快慢，可能一直挂在最慢的 ProxyIP 上。
- **测速改用 Cloudflare 托管的文件**（npm 包，约 41 MB）：经 ProxyIP，测出的是「节点 + ProxyIP」真实带宽。弹窗「测速」与自动选线均使用。可在设置 `test.speedUrl` 修改。
- **每轮测前 5 个不同 ProxyIP**（原来前 3 条线路，常是同一 ProxyIP）。
- **评分加大速度权重**：5 Mbps ×3、50 Mbps ×1.41、100 Mbps ×1、300 Mbps 以上 ×0.55；后台复测发现明显更快的 ProxyIP 会自动切换。
- **ProxyIP 池记录每个 IP 的实测带宽**，挑候选时快的优先。
- **测速失败不再编造数字**（旧版失败记 0.5、再失败减半，界面会出现「0.4」这类假值）；升级时一次性清除旧速度记录，全部重测。

## v1.2 更新（优选 IP · BestIP）

专为 edgetunnel 节点：UUID / Host / 路径 / ProxyIP 不变，自动为节点挑选 Cloudflare 优选 IP 作为连接地址（address）。

- **默认网段**：IPv6 `2606:4700:5a::/48`、`2606:4700:52::/48`、`2606:4700:57::/48`；IPv4 `172.64.229.0/24`（可在「优选 IP」页修改）。
- **每轮**：每个网段随机抽 20 个 IP（加上上一轮入选的 IP 一起复测）→ TCP 握手初筛 → 精测延迟与丢包（8 次）→ 仅测 TCP 握手延迟；对最好的 4 个逐个测下载峰值速度（每两次间隔 45~75 秒）（默认测速地址 `https://speed.cloudflare.com/__down?bytes=99999999`，直连被测 IP、以该域名作 SNI；注意 cf.090227.xyz 这类「优选域名」站点没有下载文件，不能用作测速地址） → 用真实节点参数经这些 IP 握手验证。
- **定时**：默认每 3 小时（本地时间 0/3/6/…/21 点）。按系统时间与日出日落分为白天、夜晚两个时段，各自累计成绩、各自保留前 5 名；到日出/日落自动切换。
- **达标线**（设置一次即记住）：IPv6 默认延迟 < 80 ms、峰值 ≥ 30 MB/s、丢包 0%；IPv4 单独设置（默认 150 ms / 15 MB/s / 0%）。
- **IPv6 为主、IPv4 为辅**：本机没有 IPv6 时自动全部使用 IPv4；双栈时主用全是 IPv6，另留 2 个 IPv4 作备用。
- **核心多地址**：当前时段的 5 个 IP 同时作为节点地址，核心按延迟分散连接；单个 IP 连续失败只熔断该 IP（无感切到其他 IP），5 个都不可用才用 IPv4 备用，再不行用节点原地址。
- **测量模式**：延迟只测 TCP 握手（不含 DNS/TLS/HTTP），与概览/节点页的延迟不是同一模式，数值不可互相比较；速度数据按测速地址区分，更换测速地址后旧速度数据不再参与排名并自动重测。
- **流量**：每个 IP 在测速时长（默认 3 秒）内持续下载，单个 IP 最多约 95 MB（测速文件大小），每轮最多测 4 个；自动测试时若正在大流量使用，会推迟或跳过测速。
- **edgetunnel 订阅 = 一个节点（1.2.2）**：edgetunnel 订阅里的几十个条目其实是同一个节点（同协议 + 同 UUID + 同 Host），只是 address 换成了不同的优选地址。导入/更新订阅时**按 Host 合并：每个 Host 一个节点**（订阅里有多个 Host 就是多个节点；名称为 Host，卡片显示「合并 N」；同 Host 但 UUID 不同的条目分开）：保留 Host / SNI / UUID / 路径 / TLS，**连接地址（address）由优选 IP 提供**；订阅里同端口、同 TLS 的地址只作为最后的备用（优选 IP 还没有结果时先用它们）。已有的订阅节点在升级后自动合并（保留第一个节点的 ID 与历史）；手动添加的节点、地址就是 Host 的普通直连节点不受影响。只出现一次的 Host 也单独成一个节点（按 Host + UUID 识别，订阅轮换地址不会变成新节点），是否走优选 IP 按正常的 Cloudflare 识别。
- **测速保护（1.2.1 / 1.2.2，尽量避免 speed.cloudflare.com 限流）**：
  - 实测：约 1 分钟内连续 5 次 ~95 MB 下载就会返回 403，十几分钟后自动恢复 —— 限流看的是「短时间内的大下载次数」。所以两次测速之间至少间隔 45~75 秒（随机），1 小时内最多 8 次，每轮最多测 4 个（旧默认 6 自动改为 4）；「检测测速地址」距上次测速不足 45 秒时会提示稍后再试。
  - 被限流（HTTP 429、Cloudflare 错误 1015、没有错误码的 403）→ 立即停止本轮测速，按服务器的 Retry-After 暂停；没有则暂停 1 小时，24 小时内再次被限流时加倍（最长 12 小时）。暂停期间只测延迟/丢包，速度沿用历史数据；「检测测速地址」也会暂停。页面顶部显示「测速暂停 · 几点恢复」，点击可提前解除。
  - 近 12 小时同一时段测过速、延迟/丢包没有变差的 IP 不再重复测速（沿用上次速度）。
  - 名单已满且全部达标时，延迟已不可能挤进名单的新候选不测速，每轮最多试测 2 个新候选。
  - 每日测速上限（默认 40 次，含手动测试，「高级」可调）；定时测试在整点后随机偏移 0~5 分钟。
  - 测速地址本身报错（如 403 + 错误 1034）不会被记成「该 IP 速度为 0」，连续两次就停止本轮测速。
  - 核心 1.2.1：峰值稳定后提前结束下载（线路较慢时省流量；线路很快时 95 MB 本来不到 2 秒就下完）。
  - 正常情况下每天约 25~30 次测速（原来约 48 次），约 2~3 GB。
- **关于 edgetunnel 的「在线优选」**：它的测速地址是 `<IP 编码>.bestcf.cmliussss.hidns.vip/__down?bytes=20000000`，由公共 Worker 中转 speed.cloudflare.com（多人共用）；在国内电信线路实测只有 0.3~3 MB/s，测的主要是中转速度，所以本扩展不用它，仍直连官方测速接口。
- **正在使用（1.2.2）**：「优选结果」上方实时显示此刻正经过哪些优选 IP（每 3 秒刷新），表格里对应的行标「使用中」，熔断的 IP 标「熔断」；鼠标悬停可看连接次数、占比、流量、建连耗时。核心并不固定用一个 IP：新连接会在延迟相近的主用 IP 之间分散，所以通常同时有几个在用。若此刻走的是订阅原地址（优选 IP 都不可用或还没有结果）会给出提示。核心 1.2.2 起显示「当前连接数 / 流量」；旧核心按「近 1 分钟新建连接」推断。
- **1.2.3 修复（经 edgetunnel 时「测速很慢 / 用起来很慢」）**：
  - edgetunnel 会拦截 speed.cloudflare.com / cp.cloudflare.com 等测速站点（经节点访问永远没有响应）。原来的**经节点测速**正好用它，所以永远很慢；**健康检查**有一半时间访问 cp.cloudflare.com，被误判为失败，进而熔断正常的优选 IP、来回切线路。
  - 现在：经节点测速默认改为 `https://speedtest.tokyo2.linode.com/100MB-tokyo2.bin`（旧的 Cloudflare 测速地址自动迁移；「优选 IP」直连测速不受影响，仍用 speed.cloudflare.com）；健康检查改用 `www.cloudflare.com/cdn-cgi/trace`（同时检验 ProxyIP 是否可用）。
  - 核心 1.2.3：首包超时从 5 秒放宽到 10 秒，且**不再计入优选 IP / 线路失败**（WebSocket 已连上说明 IP 是通的，慢在 Worker 拨号、ProxyIP 或目标站点）；经节点测速中途断开时按已收到的数据计速，不再记为 0。
  - 实测：同一时间、同一 IP，xray（fp=chrome）与本核心的速度同步起落（慢时都在 0.2~1 MB/s，快时 14~24 MB/s），速度主要取决于当时的线路状况。
- **需要核心 1.2.0**（「当前连接数」需要 1.2.2，上述修复需要 1.2.3）：扩展升级后请重新运行一次安装脚本（「优选 IP」或「核心」页可直接下载）。

## 一、和原插件相比解决了什么

| 问题（原插件） | Brana VPN 的做法 |
| --- | --- |
| 「vless-virtual」模式会**清空代理**，但界面仍把 ProxyIP 的地区显示成出口，实际流量是直连 | 只有真实打通的线路才会被使用；出口 IP 由浏览器经代理**实测**（Cloudflare trace + ip-api） |
| 测试失败时会**随机生成 85–175ms 的延迟**来显示 | 所有延迟、速度都是真实测量值；失败就显示失败和原因 |
| ProxyIP 被误设为 HTTP 代理导致断网 | ProxyIP 永远只写进 WebSocket 路径（`/proxyip=IP:端口`）交给节点使用，绝不设为浏览器代理 |
| 本地桥只有 HTTP，无 SOCKS5、无 `/probe`，控制接口对任何网页开放（`Access-Control-Allow-Origin: *`） | 新核心：SOCKS5 + HTTP 混合端口、真实探测/测速/出口追踪、控制接口只接受扩展来源并防 DNS 重绑定 |
| 需要手动双击 `.bat` 启动桥 | 安装一次后由浏览器通过 Native Messaging **自动启动/退出**核心，无需任何窗口 |

## 二、功能

**连通性第一的三层容灾**
1. 核心内每条连接在收到服务器首个字节前失败（握手失败、被关闭、TLS 首包超时）都会**无感重试**备用线路，并重放已发送的数据，网页感觉不到。
2. 连续失败的线路自动**熔断**，新连接直接走健康线路。
3. 浏览器级**健康检查**（默认 30 秒）连续失败立即切换；全部线路不可用时**直连兜底**保持能上网（可选「严格防泄漏」改为阻断），并按退避策略自动恢复。

**智能优选**
- 两阶段测试：先测节点本身（非 Cloudflare 网站），再在最优节点上测 ProxyIP（Cloudflare trace，拿到真实出口 IP / 国家 / 机房）。
- 同一连接测两次：**冷启动**（含握手）+ **热延迟**（纯往返），再对前 3 名**实测下载速度**，历史成功率指数衰减计入评分。
- 验证时关闭一切兜底（不放备用线路、不带 PAC 的 DIRECT），结果不会被「假通」骗过。
- 后台定期复测、维护热备；发现明显更优的线路才切换（滞回 40%，不乱跳）。

**会变通**
- 指定地区没有可用 ProxyIP → 临时使用最快线路并提示。
- ProxyIP 都不通但节点可用 → 保持连接（普通网站正常）并提示「Cloudflare 网站受限」。
- 所有节点都不通 → 自动为 Cloudflare 节点扫描**优选 IP**（随机抽样 CF 网段 → TCP 初筛 → 真实 WS 握手复核）再试。
- 订阅直连拉取失败 → 自动改经隧道拉取；订阅返回网页时自动尝试 `b64` 格式。
- Cloudflare 网站返回 **429** → 自动更换同地区的下一个 ProxyIP。
- 浏览器启动时优先**秒连上次可用线路**，再在后台补全优选。

**界面**
- 弹窗：只放常用操作 —— 动态光球（连接中旋转光环、已连接涟漪呼吸、降级琥珀色）、线路卡（出口国旗 / IP / 延迟 + 节点、ProxyIP 选择）、延迟迷你曲线、地区一键切换、优选 / 换 IP / 测速三个图标块、当前网站一键分流。未配置时显示「3 步开始使用」引导卡。
- 控制中心：主要（概览、节点）与更多（ProxyIP、分流、设置、核心、日志、帮助）分开；说明全部收进 ⓘ 气泡。
- 设置向导：核心 → 导入 → 连接 → 完成，卡片切换动画，自动前进。
- 工具栏图标实时显示出口国旗 + 状态点（内置国旗字体，Windows 也能显示国旗）。
- 可选网页右下角悬浮胶囊（国旗 / IP / 延迟 / 一键换 IP）。
- 深色 / 浅色主题，尊重「减少动态效果」系统设置。

**其他**
- 支持 `vless://`、`trojan://`（WebSocket，TLS 或明文）、订阅（Base64 / 明文）、`http://`、`https://`、`socks5://`（含账号密码）。
- ProxyIP 来源：域名（自动解析全部 IP）、`IP:端口`、`socks5://` / `http://` 链式出口、API 地址（兼容 NiREvil 列表与 CSV），内置常用来源预设。
- 分流：全局 / 仅名单，直连名单 / 代理名单，局域网地址始终直连；PAC 只做字符串匹配，无 DNS 泄漏。
- WebRTC 防泄漏、代理冲突检测、桌面通知、快捷键（`Alt+Shift+V` 开关、`Alt+Shift+N` 换 IP）、配置导入导出。

## 三、安装

### 1. 安装扩展
1. 解压 `brana-vpn.zip`。
2. Chrome 打开 `chrome://extensions/`（Edge：`edge://extensions/`），开启右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，直接选择解压出来的 **`brana-vpn`** 文件夹（文件夹里能看到 `manifest.json` 就对了）。
4. 扩展 ID 固定为 `jdnojnkpdjoijmgipheghikkkpmnaaao`（核心安装脚本已内置）。

### 2. 跟着设置向导走（推荐）
加载扩展后会自动打开「设置向导」（也可点弹窗里的「开始设置」）：

1. **核心**：点「一键安装」→ 打开下载的 `BranaVPN-Setup.cmd`（Chrome 提示时点「保留」，Windows 提示时点「运行」）→ 向导自动识别后进入下一步。
2. **导入**：粘贴订阅地址或节点链接（可多行），下方会实时显示识别结果，点「导入」。
3. **连接**：自动测试全部节点与 ProxyIP 并连接最优线路。
4. **完成**：把图标固定到工具栏即可日常使用。

### 本地核心说明（VLESS / Trojan 节点需要，一次即可）
核心基于 [Node.js](https://nodejs.org/zh-cn/download) 16+ 运行；Windows 上没有 Node.js 时，安装脚本会用 winget 自动安装 LTS 版。

- **Windows**：向导里「一键安装」，或直接双击扩展文件夹里的 `core/install-windows.cmd`（与下载的脚本完全相同，自带核心）
- **macOS / Linux**：终端执行 `bash core/install-mac-linux.sh`（同样自带核心）

脚本会把核心放到当前用户目录，并注册到 Chrome / Edge / Brave / Chromium / Vivaldi（无需管理员）。之后核心随浏览器自动启动、自动退出。

> 不想安装也可以手动运行：Windows 双击 `core/start-core-windows.cmd`，macOS/Linux 执行 `bash core/start-core.sh`，保持窗口开启即可，扩展会自动发现。
> 只使用 HTTP / HTTPS / SOCKS5（无账号）节点时**不需要**本地核心。
> 卸载核心：`core/uninstall-windows.cmd` 或 `bash core/uninstall-mac-linux.sh`。
> Windows 若弹出「已保护你的电脑」（SmartScreen），点「更多信息 → 仍要运行」即可；脚本只写入当前用户目录与注册表 `HKCU\Software\…\NativeMessagingHosts`。

### 3. 日常使用
1. 点击工具栏图标 → 点中间的光球连接 / 断开。之后一切自动：优选、健康检查、容灾、复测。
2. 想要某个国家的出口：点地区标签（如 🇯🇵 JP）。想换出口 IP：点「换 IP」。
3. **浏览器关闭后再打开会自动连接**（设置 › 常用 ›「启动自动连接」，默认开启；核心也随浏览器自动启动）。

## 四、ProxyIP 与出口说明（重要）

edgetunnel 类节点运行在 Cloudflare Workers 上：
- 访问**普通网站**时，由节点（Worker）直接连接，网站看到的是 **Cloudflare Worker 的出口 IP**；
- 访问 **Cloudflare 托管的网站**时，Worker 无法直连，必须经 **ProxyIP** 中转，网站看到的是 **ProxyIP 的出口 IP**。

因此「选择地区」= 选择 ProxyIP 的出口地区，主要影响 Cloudflare 托管的网站；控制中心会同时显示这两个出口。若希望**所有网站**都从同一个国家出去，可在 ProxyIP 来源中加入 `socks5://user:pass@host:port` 这类链式出口（需要节点支持，如 edgetunnel 2.1+）。

## 五、限制（如实说明）

- **VLESS / Trojan 需要本地核心**：Chrome 扩展无法在浏览器内实现这些协议，也不能监听本地端口，这是平台限制。核心是一个零依赖的 Node.js 程序（单文件），只监听 `127.0.0.1`。
- **暂不支持**：VMess、Shadowsocks、Hysteria/Hysteria2、TUIC、REALITY、gRPC、XHTTP（导入时会提示并跳过）。
- 本地核心的 TLS 指纹是 Node.js 的，而不是浏览器的；极少数严格的网络环境可能对此敏感。
- 只代理 TCP；浏览器在使用代理时不会走 QUIC/UDP，WebRTC 防泄漏默认开启。
- Linux 下 Snap / Flatpak 版浏览器的沙箱可能阻止 Native Messaging，此时请使用手动模式运行核心。
- 本版本在沙箱中用协议兼容的模拟 edgetunnel 服务端做了端到端测试（真实 Chromium + 扩展 + 核心），尚未在真实 edgetunnel 部署上实测；如遇兼容问题请把「日志」页和「本地核心 → 核心日志」反馈给我。
